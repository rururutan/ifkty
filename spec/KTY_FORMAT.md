# Kitty KTY/KT4 Image Format Specification

## 1. 概要

KTY/KT4は、主にPC-8801 Magical-DOSで使用されていた640ピクセル幅・デジタル8色の画像形式である。

正式な仕様書は確認されていない為、既存のローダー、公開実装、および実在するサンプルファイルを解析してまとめた非公式仕様である。

| 拡張子 | 画像サイズ | 色数 | 画素形式 |
|---|---:|---:|---|
| `.KTY` | 640×200 | 8色 | B/R/G 3プレーン |
| `.KT4` | 640×400 | 8色 | B/R/G 3プレーン |

ファイルには識別シグネチャ、画像サイズ、固定ヘッダー、パレットは存在しない。
通常は拡張子によって形式を判定する。

## 2. 基本構造

画像は横160個、縦100個の論理タイルに分割される。

- 640×200モードでは、1タイルは4×2ピクセル
- 640×400モードでは、1タイルは4×4ピクセル

ファイルは次の順序で構成される。

```text
共有タイルグループ 0
共有タイルグループ 1
...
0xFF
未指定タイルの生データ
[一部の生成プログラムでは余剰バイト]
```

共有タイルグループは、同じタイルパターンを複数の位置へ配置するための
圧縮表現である。共有タイルで指定されなかった位置は、最後の生データ領域に
左上から右下の順で格納される。

## 3. 共有タイルグループ

各グループは次の構造を持つ。

```text
BYTE mode
BYTE tile[tile_size]
rectangle rectangles[]
BYTE 0xFF
point points[]
BYTE 0xFF
```

`mode`そのものが`0xFF`の場合、共有タイルグループ列は終了し、
未指定タイルの生データへ移る。

### 3.1 モード

| mode | 画像高 | tile_size | タイルの扱い |
|---:|---:|---:|---|
| 0 | 200 | 3 bytes | 4×2ピクセル |
| 1 | 400 | 3 bytes | 2行分を上下に繰り返して4×4にする |
| 2以上 | 400 | 6 bytes | 独立した4行を持つ4×4ピクセル |

実在ファイルでは主に0、1、2が使用される。画像高は、終端に達した時点の
最後のモードが0なら200、それ以外なら400として扱う。

## 4. タイルデータ

各2行分のタイルは、Blue、Red、Greenの順に3バイトで格納される。

```text
BYTE blue
BYTE red
BYTE green
```

各バイトの上位ニブルがタイルの第1行、下位ニブルが第2行を表す。
ニブル内ではbit 3が左端、bit 0が右端のピクセルに対応する。

```text
bit:  7 6 5 4 | 3 2 1 0
      row 0   | row 1
pixel 0 1 2 3 | 0 1 2 3
```

モード2以上では、後続するもう3バイトが第3行と第4行を同じ形式で表す。

各ピクセルのカラーインデックスは、対応する各プレーンのビットから作る。

```text
color = blue_bit
      | (red_bit   << 1)
      | (green_bit << 2)
```

## 5. 矩形指定

矩形指定は、同じタイルを長方形の範囲へ一括配置する。
最初のバイトが`0xFF`なら矩形指定列は終了する。

先頭2バイトから左上座標を求める。

```text
BYTE hi
BYTE lo

offset = ((hi & 0x3F) << 8) | lo
left   = offset % 160
top    = offset / 160
```

`hi`の上位2ビットによって、右下座標の格納方法が変わる。

| `hi & 0xC0` | 後続データ | 座標の意味 |
|---:|---|---|
| `0x00` | `right`, `bottom` | 一般の矩形 |
| `0x40` | `right` | 横線。`bottom = top` |
| `0x80`または`0xC0` | `bottom` | 縦線。`right = left` |

範囲は両端を含む。

```text
for y = top to bottom
    for x = left to right
        put_tile(x, y)
```

有効範囲は`x = 0..159`、`y = 0..99`である。

## 6. 単一点指定

矩形指定列の後には、同じタイルを個別に配置する座標列が続く。

```text
BYTE x
BYTE y
...
BYTE 0xFF
```

`x`が`0xFF`なら座標列を終了する。座標はタイル単位で、
有効範囲は`x = 0..159`、`y = 0..99`である。

## 7. 未指定タイルの生データ

共有タイルグループ列を終了する`0xFF`の後には、それまで一度も指定されなかった
タイルのデータが格納される。

走査順は次のとおりである。

```text
for y = 0 to 99
    for x = 0 to 159
        if tile(x, y) is not assigned
            read and draw one tile
```

最後に使用されたモードが0の場合は、各未指定タイルを3バイトで読む。
最後のモードが0以外の場合はモード2相当として扱い、各タイルを6バイトで読む。
したがって、共有タイルでモード1が使用されていても、生データ部分は各行を
独立して持つ4×4タイルになる。

一部の実在KTYファイルには、全タイルを読み終えた後に2バイトの余剰データがある。
当時のローダーと同様、全タイルの展開完了後に残るデータは無視するのが互換性上安全である。

## 8. パレット

ファイル内にパレットは存在しない。固定のデジタル8色を使用する。
カラー番号のビット構成はB、R、Gの順である。

| Index | Red | Green | Blue | 色 |
|---:|---:|---:|---:|---|
| 0 | 0x00 | 0x00 | 0x00 | 黒 |
| 1 | 0x00 | 0x00 | 0xF0 | 青 |
| 2 | 0xF0 | 0x00 | 0x00 | 赤 |
| 3 | 0xF0 | 0x00 | 0xF0 | マゼンタ |
| 4 | 0x00 | 0xF0 | 0x00 | 緑 |
| 5 | 0x00 | 0xF0 | 0xF0 | シアン |
| 6 | 0xF0 | 0xF0 | 0x00 | 黄 |
| 7 | 0xF0 | 0xF0 | 0xF0 | 白 |

実装環境によっては、各成分の`0xF0`を`0xFF`として表示してもよい。
既存ローダーとの一致を優先する場合は`0xF0`を使用する。

## 9. デコーダー実装上の注意

- 固定ヘッダーやマジック値がないため、内容だけでの厳密な形式判定は難しい。
- 読み込みごとにファイル終端を検査し、座標がタイル範囲内か検証する。
- 矩形の右端が左端未満、または下端が上端未満の場合は破損データとして扱う。
- 共有タイルと生タイルの配置済み状態を160×100ビットまたはバイトで保持する。
- 640×200画像は1ピクセルのアスペクト比が1:2。
- 拡張子だけではモードを確定できない。画像高はストリームを解析して決定する。

## 10. 疑似コード

```text
clear assigned[100][160]
mode = 0

loop:
    mode_or_end = read_byte()
    if mode_or_end == 0xFF:
        break

    mode = mode_or_end
    shared_tile = read_tile(mode)

    while peek_byte() != 0xFF:
        rectangle = read_rectangle()
        draw shared_tile over rectangle
        mark rectangle as assigned
    consume 0xFF

    while peek_byte() != 0xFF:
        x = read_byte()
        y = read_byte()
        draw shared_tile at (x, y)
        mark (x, y) as assigned
    consume 0xFF

raw_mode = (mode == 0) ? 0 : 2
for every tile in row-major order:
    if not assigned:
        tile = read_tile(raw_mode)
        draw tile
```
